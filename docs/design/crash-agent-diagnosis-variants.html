Analisi del crash con un agente — varianti

Il dialog di crash attuale (variante A v2) riceve una terza strada: far indagare uno degli agenti dell'utente prima di segnalare. L'agente lavora in una chat in sola lettura, decide se il problema è del computer o di Flowcode, e la sua diagnosi torna da sola nel report tramite uno strumento MCP di Flowcode. Tre modi di presentarlo; il flusso dietro è lo stesso.

Il flusso (uguale per tutte le varianti)

1 · Crash rilevatoAl riavvio compare il dialog, come oggi.
→
2 · «Analizza con un agente»L'utente sceglie l'agente (solo quelli installati e collegati). Il report resta in attesa, non viene scartato.
→
3 · Chat di diagnosiNuova scheda chat nella cartella crash, permessi in sola lettura, prompt preparato con report, log e cosa controllare.
→
4 · Diagnosi allegataL'agente chiama attach_crash_diagnosis: verdetto, sicurezza, prove, soluzione locale. Passa dallo stesso filtro privacy del report.
→
5 · DecisionePC → soluzione proposta, segnalare è facoltativo. Bug → issue con sezione «Agent diagnosis». Già segnalato → commento sulla issue esistente.

A · Pulsante nel footer + pillola mentre lavora

Il minimo cambiamento: un terzo pulsante con menu agenti accanto a «Segnala». Mentre l'agente lavora il dialog si chiude e resta una pillola in basso a destra (si può usare l'app e guardare la chat). Alla fine il dialog si riapre con la diagnosi in cima.

B · Scheda «Fai indagare un agente» dentro il dialog

Più scopribile: una scheda tratteggiata nel corpo del dialog spiega l'opzione e mostra gli agenti come chip. L'analisi avanza dentro la scheda (passi in diretta, link alla chat); il dialog resta aperto ma si può ridurre. La scheda diventa il verdetto.

C · Dialog a passi: Cosa è successo → Analisi → Invia

Il dialog diventa una procedura in tre passi. Il passo 2 chiede esplicitamente se analizzare con un agente o saltare. Più guidato, ma un clic in più per chi vuole solo segnalare.

Lato chat (uguale per tutte)

La chat di diagnosi è una chat normale con una striscia in alto che dice cosa sta facendo e che è in sola lettura. Quando l'agente allega la diagnosi compare una scheda di conferma; da lì si torna al dialog.

Note e scelte già fatte (modificabili)

  • Ambito: si parte dai crash (dialog esistente) e dall'avviso di memoria alta; il meccanismo è generico («problema rilevato» → analisi), così si aggancia dopo anche ad agenti che non partono, errori della dettatura, ecc.
  • Ritorno automatico: nuovo strumento MCP attach_crash_diagnosis (verdetto machine / flowcode / unknown, sicurezza 0–1, riepilogo, prove, soluzione locale, passi per riprodurre, issue esistente). Funziona con tutti gli agenti che hanno già il server MCP di Flowcode. Se l'agente non lo chiama, il dialog mostra «Analisi senza esito» e si può segnalare come oggi.
  • Privacy: la diagnosi passa dallo stesso filtro del report (percorsi, utente, nome PC) ed è visibile e modificabile prima dell'invio. L'agente lavora nella cartella crash di Flowcode, in revisione automatica: niente modifiche o comandi rischiosi senza consenso.
  • Issue esistenti: l'agente cerca con la firma del crash tra le issue del repo pubblico (senza token); se la trova, il pulsante diventa «Commenta #123».
  • Telefono: per ora solo desktop (il dialog crash esiste solo nella finestra principale).
