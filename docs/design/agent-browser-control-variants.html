Controllo del browser da parte degli agenti

L'agente usa le schede del pannello browser (con i tuoi login) tramite nuovi tool MCP: browser_tabs, navigate, snapshot, screenshot, click/type/press/scroll, console. Di default solo sulle schede che ha aperto lui o che gli cedi; browser_eval solo su localhost e file locali (estendibile dalle impostazioni). Colore ambra = "agente al lavoro". Controllo da parte degli agenti

Gli agenti usano le schede del pannello con i tuoi login. Vedono solo le schede che aprono o che gli cedi.

Come funziona sotto

  • Windows: WebView2 espone Chrome DevTools Protocol → screenshot (Page.captureScreenshot), click e tasti veri (Input.dispatch*, isTrusted), console e rete. macOS/Linux: JS iniettato + snapshot nativo della webview; input sintetici, meno affidabili. Telefono fuori scope.
  • Snapshot: testo compatto (ruolo, nome, testo, stato) con riferimenti e1…eN, ricalcolati a ogni snapshot; i campi password risultano "[password]" senza valore. Il contenuto della pagina è marcato come non affidabile nel risultato del tool.
  • Perimetro: scheda aperta dall'agente = sua; le tue solo con "Fai controllare all'agente". Più agenti: ogni scheda ha un solo controllore.
  • Pausa: un tuo input reale nella pagina mette l'agente in pausa; i suoi tool rispondono "l'utente sta usando la scheda, attendi" finché non restituisci.
  • Fasi: 1) tabs, navigate, snapshot, screenshot, console (solo lettura) · 2) click/type/press/scroll/select/wait + consenso + cessione + indicatore · 3) rete, dialog alert/confirm, upload, viewport mobile, pagine artefatto.

Raccomandazione

A: l'unica che mostra cosa sta facendo l'agente (ultima azione + elemento evidenziato) e dove sta il pulsante Interrompi senza coprire la pagina; la barra in fondo non tocca la webview nativa (come la barra dei download). Il badge ✦ sul contatore schede e l'etichetta nell'elenco schede valgono per tutte le varianti.
