## 🧭 The browser learns new tricks

This one is mostly about the in-app browser, plus a long list of fixes from a full review of the app. Your agents can now drive their own browser tabs: they read the page, click, type and look at screenshots, and you see every move under an amber ring with a stop button always in reach. Downloads ask before saving and get their own list. Pages agents open no longer pop up twice, once in Flowcode and once in your system browser. Under the hood we fixed bugs, closed a few security gaps, cleaned up dead code and trimmed memory use on desktop and phone. The frog got itself a compass. 🐸

### ✨ New features

- **Agents can drive the browser.** New tools let an agent list its tabs, navigate, read a page as structured text, take screenshots, click, type, press keys, scroll, wait for something and read the console. On Windows the clicks and keys reach the page like real input. Agents control only the tabs they opened or the ones you hand over from the ⋯ menu ("Let the agent control this tab"), and the first time they ask, a card in the chat or tab lets you allow it for the session, allow read-only access, or say no.
- **See and stop what the agent does.** A tab under agent control gets an amber ring and a bar at the bottom with the agent's last action and a Stop button. Touch the page yourself and the agent pauses until you hand it back. Password fields are never read or typed into.
- **Browser control settings.** Settings → Browser has a new "Control by agents" section: off, ask, or allow on localhost; running code in pages (local only by default); interaction on other sites; pause when you touch the page; highlight what the agent touches.
- **Downloads ask first.** A download from the browser panel now shows a bar under the address ("Download" / "Cancel", red for programs) and lands in your Downloads folder only if you say yes. A download button appears in the header, with a dot while something is downloading, and opens the list: open, show in folder, cancel, retry, remove.
- **Right-click menu on chat links.** Right-click a link in a chat to open it in Flowcode, open it in your system browser or copy it. File paths in chats get their menu on right-click too, now including "Open in system browser" for html, svg, pdf and images.
- **Our own browser pages.** The native browser shows Flowcode's own pages for errors and new tabs (offline, refused connection, certificate problems and more), with details and an agent diagnosis button.

### 🛠 Improvements

- **Pages open once.** Agents and the dev servers they start (Vite `--open`, CRA, Python's `webbrowser`, `start`/`xdg-open`/`open` in Git Bash and WSL) now go through Flowcode, so your Browser settings decide where a page opens, and the same page asked for twice in a few seconds opens once.
- **Delegates follow the parent's mode.** A task delegated from an agent in a terminal tab starts in the same permission mode as that agent (plan or read-only stays restricted), and in read-only when the mode can't be read.
- **Calmer chat header.** The "Ready / Working" label is gone: the context ring itself turns blue while the agent works and yellow while it waits for a permission.
- **Restyled context panel.** The panel behind the context % shows the agent and model on top, a ring with used and free tokens next to Compact, two tabs (Context / Usage) and one stacked bar for what fills the context. The Delegates tab moved out: delegates live in the chat card and tray.
- **/clear keeps the agent running.** Clearing a chat renews the session on the same agent process instead of starting a new one.
- **Phone: new chats open right away.** A new chat opens straight on its chat page with a ghost loader while the agent starts, and the loading glow runs round the screen.
- **Lighter and steadier.** Image cache capped and kept fresh, previews of huge files refused instead of filling memory, offline network checks can't pile up, one Git status and one chat page request at a time, leaner uploads from the phone.
- **WSL tabs close cleanly.** Closing a WSL tab no longer wakes a stopped WSL VM, quitting doesn't wait on it, and only the tab's own processes are stopped, so tmux or ssh-agent sessions you started there survive.
- **Busy tab glow on by default.** Hidden tabs where an agent is working glow on the tab strip's edge.
- **Housekeeping.** Old design drafts, unused translations and dead components were removed.

### 🐛 Bug fixes

- **"Open in system browser" did nothing on local html/svg pages.** It now opens them in your default browser, and shows a message if opening fails.
- **Chat looked dead after /clear** with agents that reuse the session id.
- **PDF viewer could be redirected to local services:** a public PDF link redirecting to localhost is now refused.
- **Phone widgets could be triggered by other apps.** Widget buttons now carry a private token.
- **Phone could crash when coming back quickly** from a system dialog while background mode was on.
- **Secrets in the memory log:** header values, `user:pass` and bearer tokens in command lines are now masked.
- **Chat attachments** are staged in a private folder instead of the shared temp folder.
- **A stuck agent could block the whole chat,** cancel included, when it stopped reading its input.
- **Path links stayed plain text** for a minute when the agent created the file right after naming it.
- **Plugin new-tab pages** could stay blank after a reinstall instead of showing the fallback.
- **Agents stayed "offline"** forever when Flowcode started without a network.
- **Popups opened in a loop** could flood the browser with tabs; they're now rate-limited.
- **Window edges** of the undecorated window could no longer be dragged to resize on Windows.
- **Agent start, window close and phone commands** stopped working while a native browser page was open.
- **Linux:** glass transparency kept, NVIDIA Wayland glitches fixed.
- **Browser:** loading background follows the theme, fewer false overlays, and pages keep their content when hidden.
